# Lake-map PierCast point-feed validation — 2026-10-14

## Verdict

The proposed feed was rebuilt from the exact NODD LMHOFS cycles used by the
published lake-map surface runs and compared sample-by-sample with v63's
committed THREDDS regular-grid temperatures. All 32 city mappings match and
neither cycle changes a PierCast rating band, but the strict temperature gate
is **not met**: 188 of 3,872 samples (4.86%) in each cycle differ by more than
0.1°F. `PIER_CAST_TEMPERATURE_SOURCE` must remain unset/`thredds`; no production
enablement is proposed.

The difference is source-distribution interpolation, not a city mapping
difference. NODD exposes LMHOFS's native unstructured mesh; the lake-map build
interpolates that mesh to the reviewed regular-grid coordinate. v63 reads
NOAA's separately produced THREDDS regular-grid value. Repeating the comparison
with the native `nv` mesh connectivity produced the same values as the
lake-map regridder, while nearest-node sampling was materially worse.

## Reproduction

1. Export the two cycles from `pier_cast_temperature_samples` and
   `pier_cast_expansion_temperature_samples` as NDJSON (read-only).
2. Run `web/lake-map/job/validate_piercast_points.py` with both cycles and that
   reference file. It rebuilds NODD LMHOFS with the production regridder and
   emits sample-level and per-city comparisons.
3. Run `scripts/validate-piercast-lake-map-scores.ts` once per emitted feed at
   the matching `pier_cast_v3_shadow_forecast_runs.generated_at` timestamp.

No production state was changed during validation.
