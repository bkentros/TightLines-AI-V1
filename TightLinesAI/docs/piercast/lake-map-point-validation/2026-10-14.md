# Lake-map PierCast point-feed validation — 2026-10-14

## Verdict

The revised, source-aware validation gate **passes**.

- A direct THREDDS rebuild of 2026-10-14 12Z matched v63's THREDDS values to
  within 0.000002°F (0.000000°F mean), with identical mappings and no rating-
  band changes.
- Three NODD rebuilds stayed below the 0.1°F mean / 1.0°F maximum gate, with
  identical mappings and no rating-band changes.

The THREDDS validation fetched NOAA THREDDS directly even though the production
lake-map circuit breaker selected NODD for the published run. The small NODD
differences are expected distribution interpolation: NODD exposes LMHOFS's
native unstructured mesh and the lake-map build interpolates it to the exact
reviewed regular-grid cell; v63 reads NOAA's THREDDS regular-grid product.

## Validation gate

   identical grid mappings, and zero rating-band changes.
2. NODD-sourced cycles: mean absolute difference no more than 0.1°F, maximum
   absolute difference no more than 1.0°F, identical grid mappings, and zero
   rating-band changes.
3. Every cycle contains all 32 cities and forecast hours 0–120 from one source.

## Reproduction

1. Export the cycles from `pier_cast_temperature_samples` and
   `pier_cast_expansion_temperature_samples` as NDJSON (read-only).
2. Run `web/lake-map/job/validate_piercast_points.py` once with
   `--distribution thredds` and once with `--distribution nodd`. The tool uses
   the same source-specific extraction path as the scheduled lake-map job.
3. Run `scripts/validate-piercast-lake-map-scores.ts` for each emitted feed at
   the matching `pier_cast_v3_shadow_forecast_runs.generated_at` timestamp.

No production state was changed during validation.
